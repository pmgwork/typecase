# TypeCase Design

## Direction

TypeCase uses a quiet, native macOS library interface inspired by the information density and workflow of RightFont. The font previews are the primary visual content; controls remain neutral and compact.

## Color and surfaces

- Native semantic macOS colors provide automatic light and dark appearances.
- System green communicates font activation in list rows; the system accent color is reserved for selection.
- Adobe Fonts, Morisawa Fonts, LETS, and Monotype Fonts use their service names with a shared neutral cloud SF Symbol. Third-party logos are not bundled.
- Dividers and native list selection provide 1 px boundaries without shadows.
- The inspector uses `controlBackgroundColor` as the only secondary surface.

## Typography

- Interface labels use the macOS system font.
- Font content is rendered with each font's PostScript name through SwiftUI `Font.custom`.
- Primary page headings use 20–24 pt; UI labels use 11–14 pt; preview text is user-adjustable from 18–72 pt.

## Layout

- `NavigationSplitView` with sidebar navigation and font previews, plus a trailing `.inspector` panel for details.
- Toggling the inspector collapses the panel so the font list expands to the full window width.
- The PlayGround is a separate `Window` scene rather than a sheet: a scrolling canvas of text blocks with the block settings in a trailing `.inspector`, so the library stays open beside it and a page can be edited at full size. The canvas hides the list chrome and paints the chosen specimen background; the window title carries the current layout's name.
- Sidebar width: 190–260 pt.
- Main library width: 480 pt minimum.
- Inspector width: 280–400 pt.
- Repeated font rows use vertical spacing rather than cards or shadows. The header and specimen sit inside a consistent 12 pt horizontal inset so large glyphs do not touch the rounded selection highlight.
- Inspector details use a consistent eyebrow layout: each muted field label sits above its value or control. Copy Name stays beside the font name. Classification, Language, Styles, Glyphs, and Variable Axes stay above the divider for font selection. Browse Glyphs is a labeled button beside the glyph count, rather than an ambiguous header icon or an isolated action among metadata. Source and its management hint, duplicate files, and file metadata sit below it, with copyright and license last. Classification is a read-only value computed automatically; no manual assignment is available. Copyright and license values are limited to four lines and expose the full text as help.

## Components and motion

- Standard macOS controls only: `List`, `Picker`, `Slider`, `TextField`, `TextEditor`, `NSSearchField`, `Toggle`, `LabeledContent`, `.inspector`, sheets, and SF Symbols.
- The initial library scan runs off the main thread; while it is loading, the font list area shows a standard `ProgressView` row instead of the empty state. The previous scan is saved to Application Support and shown at launch, and the launch scan parses only the files and installed faces that changed since then, across every core; a provider manifest change reparses everything because sources depend on it. Listing the installed faces needs `NSFontManager` on the main thread, so it runs in slices of a few milliseconds and the window stays responsive.
- No custom badges or hand-drawn borders in list rows; the font source appears as a short secondary label (`Morisawa`, `Adobe`, `LETS`, `Local`) and is omitted for OS fonts.
- Each row starts with an activation indicator: a radio button for fonts TypeCase can activate (`circle.fill` enabled, `circle` disabled, `circle.lefthalf.filled` partial) and `lock.fill` for fonts managed by macOS or a font service. Active indicators and the lock use system green; a disabled style keeps a secondary-gray outline. Both indicators use the same size and column width so font names align, and expanded style rows repeat the indicator as a per-style activation button. Styles that share one font file toggle together, because Core Text registers font files as a unit.
- Activation is changed from the list row only; the inspector shows the management hint for sources TypeCase cannot change, not a toggle. Activating or deactivating — from a radio button, a style row, or the context menu — registers with the window's undo manager, so ⌘Z restores the previous activation state and Redo re-applies it.
- Right-clicking a font row offers Activate, Deactivate, Show in Finder, Copy Path, and a Copy Name submenu (family name, English name, PostScript names, and a CSS `font-family` declaration). The menu is attached to the selectable list so right-clicking does not draw a second context-menu preview around the row. Every item stays visible and disables itself when it does not apply: activation is disabled for sources TypeCase cannot change, Copy Name requires one selected family, and file actions require files on disk. Show in Finder reveals every file of the selection, Copy Path puts the unique paths on the pasteboard one per line, and when multiple rows are selected, Activate and Deactivate apply to every selected family and show the count in their titles.
- Filters and folder actions live in toolbar menus; the preview size sits in the toolbar as a compact “A”/slider/“A” pill in its own toolbar item with the system glass effect, separate from the filter menu and the inspector button.
- The toolbar toggles the inspector with a single ⓘ button (`info.circle`); side-by-side comparison opens from the inspector when a multi-selection is active.
- The PlayGround opens from the toolbar's `text.word.spacing` button, which adds the current font selection to the page and brings the window forward, or from File > Open PlayGround (⇧⌘G), which opens it without changing the page. A family that already has a block is selected instead of added twice, and an empty preview text leaves the new block on its language sample placeholder for direct editing.
- A PlayGround block has an H1, H2, H3, or p role in addition to its text, family and style, size, line height, tracking, and alignment. The open page has four editable specimens in H1, H2, H3, and p order, each identified by a small role label. Their stored text starts empty, but a subdued sample for each block's font language appears until the user types; if family metadata reports only Latin, the chosen face's supported languages provide a fallback. Clearing a block restores its sample. All four initial blocks use Hiragino Sans when available from the catalog, including when another block already has a font selected. Untouched older starter pages migrate in place, and a customized open page is backed up as a separate “Previous” layout before being replaced with the type scale. The toolbar's plus menu inserts a chosen role after the selected block while continuing its font; adding a font from the library chooses a role from the current preview size. Roles give a starting type scale and vertical spacing; changing role reapplies its size, line height, and tracking, while the inspector's typography controls remain freely adjustable. Layouts saved before roles existed infer a role from the stored size without changing their typography. Like the Mixed Pair editor, each specimen is an unbordered AppKit text view that can be edited in place; row height follows TextKit's wrapped layout while discarding extra font leading after the final line. The canvas has no row selection background; the editing caret and trailing inspector convey the active block, and the active block's role label extends to its font, style, and size ("H1 · Hiragino Sans · W6 · 56 pt") in a stronger tint while other blocks show only the role. The inspector edits font and typography settings; Size, Line Height, and Tracking pair each slider with a small number field whose typed values clamp to the slider's range, and a Reset to H1 (or the block's role) link appears beside the Typography heading once those values leave the role's scale. A Japanese–Latin Space slider (0–50 % of the size, 和欧間のアキ) sits with the typography controls, and an OpenType Features section lists checkboxes for the features the block's style carries, grouped as Japanese (palt, halt, chws, pkna, JIS forms…), Letters (kern, liga, calt on by default; dlig, smcp, swsh…), Figures (lnum, onum, tnum, frac, zero…), and Stylistic Sets, with a Reset link while any differs from the font's default. A new block continues the selected block's typesetting along with its font; while language samples and Clear Text live in its Block Actions menu rather than a duplicate text editor. Specimens resolve through `FontResolver`, so fonts that are not activated preview directly from their files and the Variable Axes values apply; the inspector lists the characters the block's style cannot display. Blocks reorder by dragging, and ⌫ deletes a block only when no text view is editing; Esc ends editing.
- PlayGround layouts are named pages persisted with the app's preferences; the toolbar's layout menu switches, duplicates, renames, and deletes them, and the window title shows the current name. The canvas paints the chosen specimen background and draws the blocks in the chosen text color, falling back to the system appearance, Copy as Image (⌥⌘C) renders the page at a fixed measure onto the pasteboard with a brief confirmation or an error if copying fails, and ⌥⌘I toggles the inspector.
- The Filter menu also chooses the list order: Name, Manufacturer, Recently Added, or Activated First. Favorites-first stays an app-wide preference layered on top. Recently Added uses the font file's creation date, so installed fonts with no folder stamp sort last.
- The specimen colors sit in the toolbar as a Liquid Glass capsule around a split swatch. Each half independently opens a custom SwiftUI popover: background on the left, text on the right. The same picker is used in Settings: a hue ring with a handle, a rounded-square saturation/brightness field sized to sit clear of the ring, and a per-color system reset; there are no RGB or HEX fields. The ring and disc support dragging (the control is chosen where the drag starts), keyboard adjustment, and accessibility controls; the brightness slider was replaced by the disc. Native popover surfaces and typography keep it consistent with macOS. System, Light, and Dark presets are available in the toolbar context menu. The chosen background paints the whole font list area, so specimens sit directly on it and the preview-text editor fades into the same color; while it is set, a selected row draws its own veil in the specimen text color and the system accent highlight is suppressed, so the selection belongs to the chosen palette. The inspector, sidebar, toolbar, and comparison sheet keep the system surfaces; the inspector's specimen draws no color pair and keeps the system text color, while the comparison sheet shows the color pair as a block behind its specimens. Without a chosen color the list keeps the system window color and the specimens follow the system appearance.
- The window keeps its title for the Window menu and Mission Control, but the toolbar does not draw it: the app name is already in the menu bar, so no title is repeated above the font list.
- The search field is a compact native `NSSearchField`; the leading side keeps the preview size, the specimen colors, the PlayGround button, and the Mixed Font button, and the Filter menu, the ⓘ inspector toggle, and the search field share the toolbar's trailing section.
- A floating preview-text editor is always visible below the font list: a compact Liquid Glass panel with transparent surroundings and a 75%-opaque semantic window-background underlay to keep font specimens from competing with the input text, containing a plain text field, a borderless preset menu, and a “+” button. The menu displays the current preset name and offers built-in and custom samples plus a Remove Preset submenu. The add button opens a popover for a name and preview text, initially filled with the current text; saving an existing custom name updates that preset.
- Mixed Fonts is a sidebar destination that lists saved mixed-font pairs as rows, and its Settings checkbox sits with the other sidebar items. A pair is created from the toolbar’s Mixed Font button, which opens a New Mixed Pair window of its own, like the PlayGround: one row per part of the mix on the left, grouped into one panel without a heading (Japanese, English, Numbers, Symbols), the specimen those choices draw on the right, and Cancel and Save in the window’s own toolbar at the top right. The rows start from the macOS standard fonts of each part (Hiragino Sans, Helvetica Neue) instead of the library window’s selection, and each row offers a font pop-up button plus a weight pop-up button listing that family’s styles, so every part keeps its own face. Each row's label carries a few characters of its part (あア亜, Aa, 123, &?¥) drawn in the face that will draw it; an optional part left on Automatic, its pop-up's first item, previews its fallback font in a tertiary tint. The window's toolbar repeats the library's “A”/slider/“A” size pill for its own specimen, starting from the library's preview size without changing it. New rows start from W5 for Japanese and Medium for English, Numbers, and Symbols when those styles are available; otherwise they use the family's Regular or closest-to-400 style. The window closes when the pair is saved or cancelled; the library then moves to Mixed Fonts with the new pair selected, and a pair that could not be created (either required family has no face) leaves the list unchanged. The inspector also offers a Create Mixed Pair button while a multi-selection contains both sides.
- Typesetting options are stored with a PlayGround block or a mixed pair: only the OpenType features switched away from their default (stored by tag, applied through Core Text's feature settings, and ignored by faces that lack them) and the Japanese–Latin space in em. The features a face offers come from its `GSUB` and `GPOS` feature lists (plus a legacy `kern` table), read once per face. The Japanese–Latin space is added as kerning after a kana or ideograph followed by a Latin letter or figure, and the reverse; Japanese punctuation, full-width forms, and spaces never take it. It is recomputed after every edit once the input method commits, and the copied PlayGround image and the mixed specimens apply the same rule.
- The New Mixed Pair window adds a Character group below the parts. Four equal-width fields form a two-column grid: Tracking and Tsume, then Kerning and Japanese–Latin Space. Each is a compact horizontal row with a typographic pictogram immediately before its control, without a visible text label. Tooltips and accessibility labels retain the setting names. Tracking and Tsume use editable preset combo boxes without increment/decrement steppers; both rows share the same control height. The compact value “Roman Only” keeps the narrow column readable. Kerning offers Auto, Roman Only (Metrics – Roman Only), or 0; Core Text has no optical kerning. Tracking is in 1/1000 em (−1000 to 10000) and Tsume in percent, each a native combo box that accepts typed values and Illustrator-style presets. Japanese–Latin Space offers Mojikumi steps (None, 1/8, 1/4, 1/3, 1/2 em; an older in-between value shows as Custom). Below a divider is the Proportional Metrics checkbox (`palt`). OpenType Features is a separate, initially collapsed disclosure section with the available features grouped as inline checkboxes; Reset Features clears only those overrides, preserving Kerning and Proportional Metrics. The left column scrolls when needed. A pair saves these choices and uses them in its rows, inspector, and specimen. Tracking adds space after every character; Tsume removes a share of neighboring glyphs' side bearings, read from their advances and outlines; Roman Only disables `kern` for the Japanese font only. A space typed at a Japanese–Latin boundary takes the chosen width rather than adding to it.
- A mixed pair row draws its specimen with the pair’s fonts, one per part of the text: kana, ideographs, Japanese punctuation, and the full-width forms use the Japanese font, letters the English font, digits the Numbers font, and punctuation and symbols the Symbols font. Unicode’s general categories decide the last three, so currency signs, arrows, and pictographs count as symbols. A part with no font falls back to the font that can stand in for it, so a pair missing its numbers or symbols face still draws them. A pair is named by its two required fonts, and the row's secondary label shows their styles ("W5 · Medium") so pairs of the same families in different weights read apart. The specimen follows the preview text field, the preview size, and the chosen specimen colors, and uses its own Japanese, English, digits, and symbols sample while the field is empty. The list is ordered by name and narrowed by the search text, which also matches the font names; the preview-text coverage filter applies to the library’s fonts, not to pairs.
- A pair is deleted from its row’s context menu, or from the inspector, which shows the selected pair with a large specimen, its font names, and a Delete Pair button. Pairs persist per app in `UserDefaults` with the catalog’s user data, under the faces’ family ids and PostScript names, so a pair survives a font that is temporarily unavailable: the row marks the missing font and keeps the reference.
- The preview text always filters the library: while it is not empty, the list keeps only fonts whose preview style can display every character of it. Coverage checks run off the main thread and are cached per font file.
- The inspector lists the preview-text characters the selected font cannot display; list rows stay unmarked.
- The inspector's Browse Glyphs button opens a Glyphs window for the family, like the PlayGround and New Mixed Pair windows, one window per family. The window title is the family name and its subtitle the style and character count ("12 of 1,234 characters" while a search narrows it). The window's own toolbar holds the controls, so macOS draws them as Liquid Glass over the glyphs scrolling beneath with the toolbar's scroll edge effect: a segmented Unicode-group filter (All, Latin, Kana, CJK, Symbols, Other), a style pop-up for families with several styles, and a toolbar search field that matches a character, a hexadecimal code point, or part of the Unicode name. The grid fills its width with whole-point columns divided by crossing one-pixel rules, each cell showing the glyph over its code point; hovering tints a cell and the accent color fills the selection, and each cell's context menu copies the character, code point, or name. The trailing detail pane, on the inspector's `controlBackgroundColor`, draws the selected glyph's outline on its ascender, cap-height, x-height, baseline, and descender lines with the advance width as dashed side bearings, followed by the Unicode name, code point, glyph ID and name, and advance in font units.
- The inspector adds a Variable Axes section for variable fonts: sliders set the preview instance of the family's preview style, the values apply to every preview of that face, and Reset returns to the style's own coordinates.
- The inspector reads the selected face's version, glyph count, embedding permission, designer, copyright, and license from the font file's `name`, `maxp`, and `OS/2` tables on a background task; fields the file does not carry are omitted. Classification uses face-specific OS/2 PANOSE and IBM design classes, Core Text traits, and localized CJK design names. Name fallbacks match words (Sans Serif before Serif; Monotype never means Mono). Where metadata and names give no result, a conservative Latin-outline fallback samples the stems and terminals of H and n; all three terminal measurements must agree on serif or sans, otherwise the face stays unclassified. Families use one vote per distinct face rather than whichever record arrived first. Script / Handwriting and Symbols are separate categories. The inspector displays the automatic category as plain text. Saved category overrides from older versions are ignored in both display and filtering. Classification changes invalidate the persisted scan snapshot so existing fonts are reclassified on upgrade.
- Duplicates is a sidebar destination, after Local Library and with its own Settings checkbox, that lists the families with a face whose PostScript name more than one font file provides. Apps address fonts by that name, so only one copy can be used and the rest are hidden by the family list, which shows each name once. A copy is a distinct file: a folder font TypeCase activated is the same file in the installed list and is not a duplicate of itself. The installed font list reports each name once, so the check compares installed fonts, added folders, and service fonts with each other; two installed files sharing a name are not detected. The inspector adds a read-only Duplicates section above the divider: for each duplicated face (named by style when the family has several), every copy's path with its source and name-table version as a caption, the copy Core Text resolves the name to marked In Use and listed first. A Show in Finder button reveals every copy, and each copy's context menu offers Show in Finder and Copy Path; resolving the duplicate (removing or deactivating a copy) stays with the existing actions and the file system.
- CJK fonts are recognized by reading the file itself: localized family names come from the `name` table and design languages from the `meta` table's `dlng` records, because Core Text's language list reports what a font can display rather than what it is designed for, and a Chinese font that carries a Japanese alias name would otherwise read as Japanese. A family's display name is its localized name in the highest-priority language it carries (Japanese, Simplified Chinese, Traditional Chinese, Korean); the English name stays as the secondary name, every localized name is searchable, and the inspector's Language value lists the languages the family carries, or "Latin / Other" when it has none.
- `Settings` (⌘,) has General, Sidebar, and Preview tabs with app-wide preferences shared by every window. General covers starting at login and favorites-first sorting. The last section and selected font are always restored. Sidebar contains an aligned checkbox-and-icon list of All Fonts, Favorites, System Fonts, Local Library, Duplicates, the font services, and Tags. Hiding a destination moves the selection to the first item that is still visible.
- Tags behave like Finder tags: the name is the identity, so it is unique ignoring case and surrounding whitespace and the stored spelling is reused. Tags are entities of their own and stay in the sidebar while no font carries them; the header’s plus button opens a compact naming popover to create one, and its context menu renames or deletes it everywhere. A tag is assigned from a font row’s context menu, which applies it to the whole selection, and each tag row is a selectable destination with its own count and filtered list.
- Font services are defined in one provider table (`FontProviderRegistry`): title, short label, neutral icon, management hint, empty-state message, and detection rules. Sidebar rows, Settings checkboxes, filtering, counts, and empty states derive from it. Providers appear only when the catalog contains matching fonts; a provider that loses its last font no longer has a row, and its selection moves to a visible destination after the scan completes. Detection uses service-specific paths and manifests, never manufacturer names alone: LETS manifests identify its Library/Fonts files, while Monotype Desktop App uses a hidden `.monotypefonts-*` cache. The persisted LETS id remains `fontworks` for compatibility.
- The login item mirrors the system state through `SMAppService`; when macOS asks the user to approve it, the row shows a hint and a shortcut to Login Items instead of a stale toggle.
- The Preview settings choose the app-wide preview size, background and text colors, and the sample texts for Japanese, Simplified Chinese, Traditional Chinese, Korean, and Latin used while the preview field is empty; each preview follows the family's highest-priority language. The color pickers and System/Light/Dark presets share persisted state with the toolbar controls, so changes in either location update all windows.
- The System Fonts group collapses from a leading disclosure control aligned with folder disclosure arrows; the expanded state is remembered across launches.
- The sidebar contains navigation rows only. The Folders and Tags headers keep their add (`folder.badge.plus` or `plus`) and disclosure controls visible, including for keyboard users. Each control has a fixed 24 pt slot so changing the disclosure arrow does not move the adjacent add button. Folding is animated and remembered across launches; the folder action also remains available from the File menu.
- Detected font services sit under a `Providers` section header, matching the Folders and Tags headers. The header disappears when there are no detected, visible services.
- All sidebar navigation labels use the same system font size, including indented System Fonts scopes and nested folders.
- A sidebar font count appears only on the currently selected destination.
- The sidebar uses AppKit's non-emphasized gray selection. Font and mixed-pair rows use the same rounded selection veil on both default and custom specimen backgrounds: pure white in the default dark appearance, dark in the default light appearance, or the chosen text color. The system highlight is suppressed for these rows so its extent does not change with the palette; keyboard behavior and multiple selection remain system-provided.
- The Mixed Pair editor's left column groups Required, Optional, and Typesetting as rounded panels under muted headings, like System Settings, with hairline dividers between the parts. Each part shows its name and sample above one row of native pop-ups: the font pop-up takes the remaining width and the weight pop-up keeps a fixed 92 pt, whether the style is a short name like W6 or a longer name. A legend along the bottom of the specimen names the font and style drawing each part, in a tertiary tint for an optional part that falls back to another part's font. While the text is empty, the sample specimen draws at 70 % opacity so it still reads as the mix it previews.
- Font previews in lists are single-line with tail truncation so row heights stay constant; the inspector and comparison allow two lines.
- Double-clicking a font row expands its styles, including families with just one style; a second double-click collapses them. Expanded style rows list each face light-to-heavy by font weight, with the style name as the tiebreaker so styles order the same for installed and folder fonts. Only one family is expanded at a time, and selecting another font collapses the expanded styles.
- Disabled local fonts are previewed directly from their font-file descriptors without registering or activating them.
- Library edits update only the affected family so the list does not rebuild or re-animate during state changes. Changing destination or filters keeps the selection on a visible row, or clears it when the result is empty, so the inspector always describes the visible list.
- State changes use native macOS motion and accessibility behavior; no decorative animation is added.

- Folder rows use a three-state activation indicator (all active, mixed, or inactive) in place of the leading folder icon, leaving the trailing edge for the count. Clicking it directly deactivates an entirely active folder, or activates all files when inactive or mixed. The tooltip shows active/total managed font files; the context menu retains explicit Activate All / Deactivate All actions. Operations include descendants, target files within the folder rather than every style of a matching family, share the existing progress and failure reporting, and support Undo. Counts describe files because a font collection registers as one unit.

- PlayGround uses a visible layout menu and Add Block label in the toolbar, a restrained outline around the selected specimen, and a centered canvas measure capped at 900 pt. The inspector pins the block role and actions above its scrolling content. Font and style use shared native pop-up controls that fill the column; typography values use a two-column numeric grid, alignment spans the panel, and OpenType features start collapsed.

- The category filter menu draws Serif, Monospaced, Display, and Script / Handwriting labels in representative fonts using native attributed NSMenuItem titles. Symbols and Unclassified retain readable system text. Category filtering, activation filtering, and sorting keep their existing meanings and checkmarks.
